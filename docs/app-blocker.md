# اپ‌بلاکر (اسپک ۱E) — راهنمای فنی

وضعیت: **نوشته شده، هنوز کامپایل و روی گوشی تست نشده** (محیط ساخت نبود). اولین کار: بیلد در GitHub Actions، رفع خطاهای احتمالی Kotlin/Dart، و بعد چک‌لیست پایین روی Poco X7 Pro.

## معماری
- **Kotlin بومی** (`android_src/kotlin/blocker/`) در بیلد توسط `tool/patch_android.py` داخل پروژه‌ی اندروید کپی می‌شود (کنار `MainActivity.kt` تازه که کانال را ثبت می‌کند).
  - `BlockerStore`: همه‌ی وضعیت در SharedPreferences (کلید `omid_blocker`)؛ بازه‌ها، اجازه‌ها، شمارش‌ها، رویدادها، جلسه‌ی سریع، قفل قطع کامل، ساعت قابل‌اعتماد.
  - `BlockerService`: سرویس پیش‌زمینه (`specialUse`). فقط داخل بازه‌ی فعال، هر ~۰٫۸ ثانیه با `UsageStatsManager` اپ جلوی صفحه را می‌خواند. بیرون از بازه‌ها هیچ‌چیز خوانده نمی‌شود.
  - `BlockActivity`: صفحه‌ی بلاک (با اجازه / قطع کامل). کنارش یک **پوشش فوری** (overlay) هست: هم اپ ممنوع را همان لحظه می‌پوشاند، هم (اندروید ۱۵) شرط باز کردن Activity از پس‌زمینه را برآورده می‌کند. اگر Activity باز نشد، همان پوشش دکمه‌ی «برگرد به درس» دارد.
  - `BootReceiver`: بعد از ریست یا آپدیت اپ، سرویس را دوباره بالا می‌آورد.
  - `BlockerPerms`: وضعیت مجوزها و باز کردن صفحه‌ی درست تنظیمات (شیائومی/HyperOS هم).
  - `BlockerChannel`: `MethodChannel('omid/blocker')`.
- **Flutter**: `lib/core/blocker.dart` (مدل و رابط)، `lib/features/blocker/` (صفحه‌ی اصلی، بازه‌ی جدید، مجوزها، انتخاب اپ، شیت «بلاک کن در این جلسه»). ورودی‌ها: تنظیمات ← «اپ‌بلاکر»، و دکمه‌ی «بلاک کن در این جلسه» بالای اتاق تمرکز.

## قواعد اسپک که پیاده شده
- خاموش پیش‌فرض؛ فقط دانش‌آموز روشن می‌کند؛ قبل از روشن شدن صفحه‌ی توضیح (چه چیزی خوانده می‌شود).
- حالت هر بازه هنگام ساختن انتخاب می‌شود. `soft`: ۳۰ ثانیه صبر ← ۵/۱۰/۱۵ دقیقه ← تأیید نهایی؛ سقف اجازه (پیش‌فرض ۳، قابل تغییر ۱ تا ۵)؛ اجازه هیچ‌وقت از پایان بازه بیشتر نمی‌شود. `strict`: هیچ دکمه‌ی بازکردنی نیست.
- تا وقتی بازه‌ی `strict` فعال است: کلید اصلی، ساخت/ویرایش/حذف بازه‌ها، و خاموش‌کردن بلاکر قفل است (در خود Kotlin اعمال می‌شود، نه فقط در UI).
- همیشه آزاد: امید، تلفن (دایلر پیش‌فرض + اپ تماس)، پیام (اپ SMS پیش‌فرض)، ساعت/آلارم، دوربین، لانچر، SystemUI. این‌ها در فهرست انتخاب اپ نیستند و در `decide()` هم دوباره فیلتر می‌شوند.
- بدون `QUERY_ALL_PACKAGES`؛ فقط `<queries>` با intent لانچر.
- `permission_revoked`: اگر Usage Access یا Overlay وسط کار برداشته شود، رویداد ثبت و اعلان به دانش‌آموز داده می‌شود.
- ضدّ دستکاری ساعت: ساعت قابل‌اعتماد = ساعت گوشی در لحظه‌ی لنگر + `elapsedRealtime`. جهش بیش از ۲ دقیقه نادیده گرفته و به‌صورت `clock_changed` ثبت می‌شود. بعد از هر پاسخ سرور (هدر `Date`) لنگر با ساعت سرور تنظیم می‌شود (`Api.onServerDate`).
- رویدادها: `blocked | unlock_requested | unlocked | strict_denied | permission_revoked | clock_changed`. فقط شمارش و نام اپ بلاک‌شده؛ بدون محتوای صفحه، تاریخچه یا فهرست اپ‌های نصب‌شده.

## مجوزها (به ترتیب)
1. Usage Access (`PACKAGE_USAGE_STATS`) — لازم.
2. نمایش روی اپ‌های دیگر (`SYSTEM_ALERT_WINDOW`) — لازم.
3. اعلان — توصیه.
4. بدون محدودیت باتری — توصیه.
5. فقط شیائومی/Poco (HyperOS): «نمایش پنجره‌ی پاپ‌آپ در پس‌زمینه» و «شروع خودکار». این دو را اندروید قابل پرسیدن نمی‌کند (تقریبی خوانده می‌شود)، پس دکمه‌ی «انجام دادم» دارند. بدون پاپ‌آپ پس‌زمینه، صفحه‌ی بلاک روی HyperOS باز نمی‌شود.

## ارسال شمارش‌ها به مشاور (فعلاً خاموش)
`Config.sendBlockerEvents = false`. چون کد Worker در پروژه نیست، مسیر زیر باید به Worker اضافه شود، بعد پرچم را `true` کن.

`POST /blocker/events` (توکن دانش‌آموز):
```json
{ "day": "2026-11-16",
  "events": [ { "ts": "2026-11-16T12:30:00.000Z", "package": "com.instagram.android",
                "label": "Instagram", "event": "blocked", "duration_sec": 0 } ] }
```
پاسخ: `{ "ok": true }`. اپ از `OfflineQueue` می‌فرستد، پس تکراری‌شدن ممکن است؛ سمت Worker با `(student_id, ts, package, event)` یکتا کن.

```sql
CREATE TABLE IF NOT EXISTS blocker_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  student_id TEXT NOT NULL,
  day TEXT NOT NULL,
  ts TEXT NOT NULL,
  package TEXT,
  label TEXT,
  event TEXT NOT NULL,
  duration_sec INTEGER DEFAULT 0,
  UNIQUE (student_id, ts, package, event)
);
```
نمایش برای مشاور (هنوز ساخته نشده): در گزارش شبانه/تب آمار، شمارش `blocked + strict_denied` و `unlocked` به تفکیک اپ، و هشدار برای `permission_revoked` و `clock_changed`.

## محدودیت‌های صادقانه
- نفوذناپذیر نیست: دانش‌آموز می‌تواند اپ را پاک کند، مجوز را از تنظیمات اندروید بردارد یا گوشی را فکتوری کند. (برداشتن مجوز تشخیص و گزارش می‌شود.)
- فقط پکیج اپ بلاک می‌شود؛ سایت‌ها در مرورگر نه.
- بعد از ریست گوشی تا اولین ارتباط با سرور، ساعت قابل‌اعتماد از ساعت گوشی شروع می‌شود (دستکاری حین خاموشی قابل تشخیص نیست؛ بعد از اولین پاسخ سرور اصلاح و گزارش می‌شود).
- شمارش‌های بلاکر وقتی اپ بسته است روی گوشی جمع می‌شوند و با باز شدن اپ فرستاده می‌شوند (کار پس‌زمینه‌ی WorkManager به بلاکر وصل نیست).
- حالت چندپنجره‌ای/تقسیم صفحه فقط اپ «آخرین resume‌شده» را می‌بیند.

## چک‌لیست تست روی Poco X7 Pro
- [ ] بلاکر خاموش شروع می‌شود؛ بدون مجوز روشن نمی‌شود.
- [ ] با مجوزها: بازه‌ی ۲ دقیقه‌ای با اینستاگرام (soft) بساز؛ بازکردن اینستاگرام صفحه‌ی بلاک را می‌آورد (با صفحه‌ی روشن، و بعد از بستن کامل امید).
- [ ] «اجازه می‌خوام»: ۳۰ ثانیه، رفتن از صفحه شمارش را صفر می‌کند؛ بعد مدت، تأیید؛ اپ باز می‌شود و بعد از مدت دوباره بلاک می‌شود؛ سقف اجازه رعایت می‌شود.
- [ ] strict: دکمه‌ی بازکردنی نیست؛ کلید اصلی و بازه‌ها قفل‌اند؛ تلفن، پیام، ساعت، دوربین باز می‌شوند.
- [ ] ریستارت گوشی: سرویس خودش بالا می‌آید و بلاک ادامه دارد.
- [ ] برداشتن Usage Access: اعلان و رویداد `permission_revoked`.
- [ ] تغییر ساعت گوشی ۱۰ دقیقه جلو/عقب: بازه‌ها جابه‌جا نمی‌شوند؛ `clock_changed` ثبت می‌شود.
- [ ] اتاق تمرکز ← «بلاک کن در این جلسه» هر دو حالت؛ پایان جلسه‌ی soft بلاک را برمی‌دارد.
- [ ] باتری: یک روز عادی، مصرف نوتیف/سرویس قابل‌قبول.
